    **Pattern from 08-RESEARCH.md (lines 455-474):**
    ```typescript
    async validateBatchItems(items: ZoteroItem[]): Promise<void> {
      const warnings = new Map<string, number>();

      for (const item of items) {
        const validation = validateItem(item);
        for (const field of validation.missingFields) {
          const key = `Missing ${field}`;
          warnings.set(key, (warnings.get(key) ?? 0) + 1);
        }
      }

      // Show ONE aggregated notice
      if (warnings.size > 0) {
        const summary = Array.from(warnings)
          .map(([issue, count]) => `${count}x ${issue}`)
          .join(', ');
        new Notice(`Validation: ${summary}`, 5000);
      }
    }
    ```

    **Implementation details:**
    - Add private field `validationWarnings: Map<string, number>` to TriageView class
    - In `loadBatch()` method, clear warnings map: `this.validationWarnings.clear()`
    - In validation flow (where `validationService.validate()` is called), collect warnings instead of showing individual notices
    - For each failed validation: increment count in map for each missing field (`Missing title`, `Missing DOI`, etc.)
    - After batch generation completes (end of `loadBatch()`), show aggregated notice if warnings exist
    - Notice format: "Validation: 15x Missing DOI, 8x Missing authors, 3x Missing title" (5 second auto-dismiss)
    - Display timing: After batch completes, before user sees first card (per 08-CONTEXT.md line 35)

    **Why aggregation:** Prevents notice spam during large batch operations. User sees ONE summary of all validation issues instead of individual notices per item. Still actionable (user knows what fields to fix in Zotero).
