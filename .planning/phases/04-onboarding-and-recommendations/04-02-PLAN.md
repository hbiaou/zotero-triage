<task type="auto">
  <name>Task 2: Implement RecommendationEngine with multi-signal scoring</name>
  <files>
    src/recommendations/recommendation-engine.ts
  </files>
  <action>
Create RecommendationEngine class with scoring algorithm (per RESEARCH.md Pattern 2):

**Constructor:**
- Accepts ProfileService and ZoteroConnector references

**Main method:**
```typescript
scoreItems(items: ZoteroItem[], config?: Partial<RecommendationConfig>): ScoredItem[]
```

**Scoring algorithm:**
1. If no profile exists, return items with random scores (cold-start handling)
2. For each item, calculate:
   - **Tag score:** Count matching tags between item and profile, sum their weights from profile.tags map
   - **Author score:** Count matching authors (case-insensitive), sum their weights from profile.authors map
   - **Keyword score:** Extract keywords from item title + abstract using keyword-extractor, count matches with profile.keywords, sum weights
   - **Raw score:** (tagScore * ProfileWeights.tagWeight) + (authorScore * ProfileWeights.authorWeight) + (keywordScore * ProfileWeights.keywordWeight)
   - **Recency boost:** If config.recencyBoost and item.year >= (currentYear - config.recencyYears), multiply raw score by config.recencyMultiplier
   - **Final score:** Normalize to 0-100 range (divide by max score in batch, multiply by 100)

**Diversity handling:**
When config.relevanceVsDiversity > 0:
- Sort by score descending
- Apply diversity penalty: if item has signals matching previous selected items, reduce score by (diversityWeight * matchCount)
- Re-sort after penalty applied
- This spreads recommendations across different topics when diversity > 0

**Default config:**
- relevanceVsDiversity: 0 (pure relevance)
- recencyBoost: true
- recencyYears: 3
- recencyMultiplier: 1.5

**Cold-start handling:**
When profile is null or empty (no signals):
- Return items with randomized scores (Math.random() * 100)
- This gives users a starting point to begin accepting/rejecting

Pattern: Follow service class pattern (constructor with dependencies, main scoring method, helper methods for signal matching).

Use RESEARCH.md Algorithm 1 (Frequency-Weighted Scoring) as reference.

  <name>Task 3: Implement AdaptiveLearner for profile evolution</name>

  </files>
  <action>
Create AdaptiveLearner class for learning from user feedback (per RESEARCH.md Pattern 4):

**Constructor:**
- Accepts ProfileService and keyword-extractor references

**Main methods:**
```typescript
learnFromAccept(item: ZoteroItem): void
learnFromReject(item: ZoteroItem): void
```

**Learning algorithm:**

For accepts:
1. Extract signals from item (tags, authors, keywords from title+abstract)
2. For each signal:
   - If signal exists in profile, boost weight by ACCEPT_BOOST (from ProfileService constants)
   - If signal doesn't exist, add with initial weight of 1.0
3. Update profile via profileService.recordAccept(item)
4. Trigger debounced save

For rejects:
1. Extract signals from item (same as accepts)
2. For each signal:
   - If signal exists in profile, diminish weight by REJECT_PENALTY (from ProfileService constants)
   - Never remove signals completely (respect MIN_WEIGHT floor)
   - If signal doesn't exist, ignore (don't add negative signals)
3. Update profile via profileService.recordReject(item)
4. Trigger debounced save

**Signal extraction helper:**
```typescript
private extractSignals(item: ZoteroItem): { tags: string[], authors: string[], keywords: string[] }
```
- Tags: item.tags directly
- Authors: item.authors array
- Keywords: extractKeywords(item.title + ' ' + item.abstractNote)

**Why this works (per RESEARCH.md):**
- Accepted items reinforce the profile (boost matching signals)
- Rejected items diminish the profile (reduce matching signals)
- Over time, profile converges to user's true interests
- Debounced saves prevent excessive disk I/O during batch processing

Pattern: Service class with dependencies, methods for each user action (accept/reject), helper for signal extraction.
