  <name>Task 2: Implement ProfileService for profile management</name>
  <files>
    src/profile/profile-service.ts
  </files>
  <action>
Create ProfileService class with methods:

**Constructor:**
- Accepts plugin instance reference
- Initializes empty profile if none exists

**Core methods:**
- `getProfile(): UserProfile | null` - Returns current profile
- `createProfile(seedPaperIds: string[], preferences: { relevanceVsDiversity: number, recencyBoost: boolean }): UserProfile` - Creates new profile from seeds (signals extracted later)
- `updateProfile(updates: Partial<UserProfile>): void` - Merge updates into profile
- `hasProfile(): boolean` - Check if profile exists
- `clearProfile(): void` - Reset to null

**Signal management:**
- `addSignal(signal: ProfileSignal): void` - Add or increment weight for signal
- `removeSignal(type, value): void` - Remove signal from profile
- `adjustWeight(type, value, delta): void` - Increment/decrement signal weight
- `getTopSignals(type, limit): ProfileSignal[]` - Get top N signals by weight

**Persistence:**
- `async save(): Promise<void>` - Debounced save to plugin.settings.userProfile
- Use lodash.debounce with 2000ms delay (matching registry pattern from 01-03)
- Call plugin.saveSettings() after updating settings.userProfile

**Learning methods:**
- `recordAccept(item: ZoteroItem): void` - Boost weights for matching signals
- `recordReject(item: ZoteroItem): void` - Diminish weights for matching signals

Pattern: Follow RegistryService structure (class with plugin ref, debounced saves, CRUD methods).

Weight adjustment constants:
- ACCEPT_BOOST = 0.2 (add to matching signal weights)
- REJECT_PENALTY = -0.1 (subtract from matching signal weights)
- MIN_WEIGHT = 0.1 (floor, never go below)
- MAX_WEIGHT = 5.0 (ceiling, prevents runaway weights)

  <action>
Create keyword extraction utility with frequency-based approach:

**Main function:**
```typescript
export function extractKeywords(text: string, options?: { minLength?: number, maxKeywords?: number }): string[]
```

**Algorithm (per RESEARCH.md):**
1. Lowercase and tokenize (split on whitespace/punctuation)
2. Filter stopwords (common words: the, a, an, of, in, to, for, with, on, at, from, by, about, as, into, through, during, including, etc.)
3. Filter by min length (default 4 characters)
4. Count frequency of each term
5. Return top N terms by frequency (default 10)

**Stopword list:**
Include ~50 most common English stopwords (the, a, an, is, are, was, were, be, been, being, have, has, had, do, does, did, will, would, could, should, may, might, must, can, of, in, to, for, with, on, at, from, by, about, as, into, through, during, including, under, over, between, among, etc.)

**Edge cases:**
- Empty string -> []
- Single word -> [word] if not stopword
- Hyphenated terms -> split and extract both parts

Use RESEARCH.md recommendations for simple frequency-based extraction (no external libraries needed).
