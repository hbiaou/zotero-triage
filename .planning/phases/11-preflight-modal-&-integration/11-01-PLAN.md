  <action>
Create PreflightService class that orchestrates sequential health checks (trash → duplicates → groups).

**src/services/preflight-service.ts:**
- Interface `PreflightCheckResult` with fields:
  - `trashCount: number`
  - `trashError?: string`
  - `duplicateCount: number`
  - `duplicateSampleGroups: DuplicateGroup[]`
  - `duplicateError?: string`
  - `hasGroupLibraries: boolean`
  - `groupLibrariesError?: string`

- Class `PreflightService`:
  - Constructor takes `ZoteroConnector` and `DuplicateDetectionService` (from Phase 10)
  - Method `async executePreflightChecks(): Promise<PreflightCheckResult>`
    - Sequential execution (not parallel): trash count → duplicate detection → group library check
    - Try/catch wrapper for each check — on error, set error string field and continue
    - Return result object with all counts (0 on error, not throwing)

  - Private method `async getTrashCount(): Promise<number>`
    - Execute `TRASH_COUNT_QUERY` via `this.connector.db.exec()`
    - Extract count from results array
    - Return 0 if query fails (graceful degradation)

  - Private method `async hasGroupLibraries(): Promise<boolean>`
    - Execute `GROUP_LIBRARY_QUERY` via connector
    - Return true if count > 0, false otherwise
    - Return false on error (assume no group libraries)

**src/db/queries.ts:**
Add two SQL queries:

```typescript
export const TRASH_COUNT_QUERY = `
SELECT COUNT(*) as count
FROM deletedItems
WHERE libraryID = (SELECT libraryID FROM libraries WHERE type = 'user' LIMIT 1)
`;

export const GROUP_LIBRARY_QUERY = `
SELECT COUNT(*) as count
FROM libraries
WHERE type != 'user'
`;
```

**Import requirements:**
- Import `DuplicateDetectionService` and `DuplicateGroup` from '../services/duplicate-detection-service'
- Import `ZoteroConnector` from '../db/zotero-connector'
- Import queries from '../db/queries'

**Error handling philosophy:**
Follow Phase 10 pattern: return 0 counts on error, log to console, never throw. Errors populate `*Error` fields in result object for UI display.

**Why sequential, not parallel:**
Per RESEARCH.md: UI simplicity (single progress message), database load distribution, predictable timing for 15-second timeout logic.

Create PreflightModal that displays preflight results with color-coded severity levels and acknowledgment workflow.

**src/ui/preflight-modal.ts:**
- Import Obsidian Modal, ZoteroConnector, PreflightService, DuplicateDetectionService
- Class `PreflightModal extends Modal`:
  - Constructor parameters: `app`, `connector`, `duplicateDetectionService`, `onComplete: () => void`
  - Private fields:
    - `checkStartTime: number` (for 15-second timeout tracking)
    - `isChecking: boolean` (progress state flag)
    - `timeoutTimer: NodeJS.Timeout | null` (15-second timer)

  - Method `async onOpen(): Promise<void>`
    - Set modal title: "Library Health Check"
    - Add CSS class: `zotero-triage-preflight`
    - Create progress container div (for spinner + status messages)
    - Start checks immediately:
      - `this.checkStartTime = Date.now()`
      - `this.isChecking = true`
      - Set 15-second timeout: `setTimeout(() => this.showTimeoutMessage(), 15000)`
      - Call `await this.runPreflightChecks()`
      - `this.isChecking = false`
    - On success: call `this.displayResults(result)`
    - On error: call `this.displayCatastrophicError(err)`

  - Private method `async runPreflightChecks(): Promise<void>`
    - Create `PreflightService` instance
    - Show progress: "Checking library health..."
    - Call `service.executePreflightChecks()`
    - Return result

  - Private method `showTimeoutMessage(): void`
    - If `this.isChecking` still true after 15s, update progress message
    - Add message: "Large library detected. This may take up to a minute..."
    - Add CSS class `preflight-timeout-notice` for styling

  - Private method `displayResults(result: PreflightCheckResult): void`
    - Clear progress container
    - Create results container
    - Display 3 advisory sections (trash, duplicates, groups) with severity styling:

      **Trash advisory (if trashCount > 0):**
      - Severity: `warning` (yellow)
      - Count: Display exact number "47 items in trash"
      - Message: "Trash items may affect recommendation accuracy"
      - Action: "In Zotero, go to Trash collection to review and empty"

      **Duplicate advisory (if duplicateCount > 0):**
      - Severity: `critical` (red)
      - Count: Display exact number "12 duplicate items detected"
      - Message: "Duplicates can cause items to appear multiple times in batches"
      - Action: "In Zotero, go to Duplicate Items in left sidebar to merge"

      **Group library advisory (if hasGroupLibraries):**
      - Severity: `info` (blue)
      - Count: N/A (just presence indicator)
      - Message: "Group libraries automatically excluded from recommendations"
      - Action: None needed

    - If any check has error, display error message in that section
    - Add acknowledgment button: "I Understand" (primary CTA styling)
    - Button click handler: call `this.onComplete()`, then `this.close()`

  - Private method `displayCatastrophicError(err: Error): void`
    - Clear contentEl
    - Show error heading: "Preflight Check Failed"
    - Show error message from exception
    - Show bypass message: "You can continue to onboarding without the health check."
    - Add "Continue Anyway" button (primary CTA)
    - Button click: call `this.onComplete()`, then `this.close()`

  - Method `onClose(): void`
    - Clear timeout timer if exists: `if (this.timeoutTimer) clearTimeout(this.timeoutTimer)`
