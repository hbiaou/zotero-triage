# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-01-25
**Phases:** 1-5
**Total Plans:** 23

## Overview

This roadmap delivers a progressive literature processing plugin for researchers with massive Zotero libraries. Phase 1 establishes the foundation (SQLite access, state management, basic note generation). Phase 2 builds the core differentiator (batch-based triage workflow). Phase 3 adds quality gates to prevent importing incomplete metadata. Phase 4 enables intelligent onboarding and recommendations. Phase 5 polishes for production use with performance optimization and cross-platform testing.

## Phases

### Phase 1: Foundation
**Goal**: Plugin can read Zotero database, persist processing state, and generate basic literature notes

**Depends on**: Nothing (first phase)

**Requirements**: ZCON-01, ZCON-02, ZCON-03, ZCON-04, RGST-01, RGST-02, NOTE-01, NOTE-02, NOTE-03, NOTE-04, SETT-01, SETT-02

**Success Criteria** (what must be TRUE):
  1. User can configure Zotero database path and plugin connects to database successfully
  2. Plugin reads items from Zotero database (5000+ items) without freezing Obsidian UI
  3. Plugin detects Zotero schema version (6.x vs 7.x) and adapts field queries
  4. User can manually import a single item and a literature note is created with YAML frontmatter (title, authors, year, DOI, Zotero link, PDF path)
  5. Processing registry persists item state (imported/unprocessed) and survives Obsidian restarts

**Plans**: 4 plans

Plans:
- [x] 01-01: Project setup, build tooling, plugin scaffold
- [x] 01-02: Zotero database connector with sql.js and EAV queries
- [x] 01-03: Settings tab and registry service for state persistence
- [x] 01-04: Search modal, preview modal, and note generator

**Details:**
Implemented SQLite database connector using sql.js with chunked processing (50 items/chunk), registry service with debounced persistence (2000ms), note generator with YAML frontmatter and proper escaping, cross-platform database path detection, and settings UI with connection testing.

### Phase 2: Batch Workflow
**Goal**: Users can process Zotero items in batches using a card-based triage interface with Accept/Reject/Defer actions

**Depends on**: Phase 1

**Requirements**: BTCH-01, BTCH-02, BTCH-04, TRIG-01, TRIG-02, TRIG-03, TRIG-04, RGST-03, RGST-04, SETT-03

**Success Criteria** (what must be TRUE):
  1. User can generate a batch of 5 candidate items from their Zotero library
  2. Triage dashboard displays items as cards showing title, authors, year, abstract, and item type
  3. User can Accept an item and it creates a literature note immediately
  4. User can Reject an item and it never appears in future batches
  5. User can Defer an item and it may appear in future batches
  6. Dashboard shows batch progress (e.g., "3/5 processed")
  7. Registry never proposes the same item twice (deduplication enforced)
  8. User can see stats dashboard showing items imported, rejected, and pending

**Plans:** 3 plans

Plans:
- [x] 02-01: Batch service, registry deferred state, batch size setting
- [x] 02-02: Triage view with cards, actions, and undo notices
- [x] 02-03: Stats panel, session tracking, batch completion flow

**Details:**
Implemented batch generation with configurable size (default 5), card-based triage UI with Accept/Reject/Defer actions, undo capability with 3-second window, session tracking with velocity metrics (24h and 7d), stats dashboard showing library overview, and theme-compatible CSS using Obsidian variables.

### Phase 3: Quality Gates
**Goal**: Plugin validates metadata completeness before import and enhances literature notes with configurable quality gates

**Depends on**: Phase 2

**Requirements**: QUAL-01, QUAL-02, QUAL-03, QUAL-04, QUAL-05, SETT-04

**Success Criteria** (what must be TRUE):
  1. Plugin blocks import if required fields are missing (e.g., journal article missing DOI or year)
  2. User sees exactly which fields are missing when import is blocked
  3. User can click a link to open the item in Zotero and fix metadata
  4. User can override quality gate and force import if needed
  5. Required fields are configurable per item type (journal article vs book vs conference paper)
  6. Imported notes have complete, structured YAML frontmatter with all available metadata

**Plans:** 3 plans

Plans:
- [x] 03-01: Validation service, quality gate settings, enhanced YAML
- [x] 03-02: Validation UI, override modal, action handlers
- [x] 03-03: Complete publisher validation for books (gap closure)

**Details:**
Implemented Zod-based validation service with per-item-type schemas (journal articles, books, conference papers), override modal for incomplete items with explicit confirmation, enhanced YAML with collections/publisher/ISBN fields, zotero://select deep links for external metadata fixes, and validation badges integrated into card rendering.

### Phase 4: Onboarding & Recommendations
**Goal**: New users can quickly set up their profile through a guided wizard, and batches are intelligently generated based on user interests

**Depends on**: Phase 3

**Requirements**: ONBD-01, ONBD-02, ONBD-03, ONBD-04, BTCH-03, SETT-05

**Success Criteria** (what must be TRUE):
  1. First-time users see a multi-step setup wizard that guides configuration
  2. User can select 5-15 seed papers to establish their interest profile
  3. Plugin extracts keywords and authors from seed papers for profile
  4. User can skip wizard and configure manually via settings
  5. Batch generation recommends items similar to user's profile (matching keywords and authors)
  6. User can modify their profile (re-select seed papers or update preferences)
  7. Recommended batches feel relevant to user's research interests

**Plans:** 5 plans

Plans:
- [x] 04-01: Profile service, keyword extraction, type definitions
- [x] 04-02: Recommendation engine with multi-signal scoring, adaptive learning
- [x] 04-03: Setup wizard modal, seed paper picker, profile initialization
- [x] 04-04: Batch service enhancement, profile editor UI
- [x] 04-05: Wizard trigger, learning integration, verification

**Details:**
Implemented multi-step setup wizard (database → preferences → seed papers), profile-based recommendation engine with multi-signal scoring (keywords, authors, recency), adaptive learning from user feedback (accept: +0.2 weight, reject: -0.1 weight), frequency-based keyword extraction with 50+ stopwords, profile editor in settings tab with top-10 signals display, and wizard trigger on first load with 1-second delay.

## Milestone Summary

**Key Decisions:**
- Direct SQLite access via sql.js for performance (validated: handles 5000+ items smoothly)
- Keywords + Authors for profile (validated: adaptive learning works without vectors)
- Lazy database initialization (validated: <50ms startup achieved)
- Exponential backoff for SQLITE_BUSY (validated: prevents concurrent access failures)
- Seed paper range 5-15 (validated: flexible enough for different use cases)

**Issues Resolved:**
- SQLite locking: Mitigated with sql.js read-into-memory approach
- Schema changes: Resolved with version detection (100-200 range)
- UI freezing: Resolved with chunked processing (50 items/chunk)
- SQLITE_BUSY errors: Resolved with exponential backoff retry (5 attempts)
- Cross-platform path bugs: Resolved with normalization utilities

**Issues Deferred:**
- Tag extraction: ZoteroItem schema missing tags field (deferred to v1.1)
- Empty profile warning: ProfileInitializer doesn't warn user when profile empty (deferred to v1.1)
- Granular batch scoring progress: No progress updates during scoring phase (deferred to v1.1)
- Override modal explanations: Missing field requirement explanations (deferred to v1.1)

**Technical Debt Incurred:**
None — Clean implementation throughout all phases.
