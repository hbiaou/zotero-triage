# Requirements: Zotero Triage

**Defined:** 2025-01-22
**Core Value:** Users can progressively process their Zotero backlog without overwhelm, ensuring only quality notes enter their vault.

## v1 Requirements

Requirements for MVP release. Each maps to roadmap phases.

### Zotero Connection

- [x] **ZCON-01**: Plugin can read items from local Zotero SQLite database (read-only) — ✅ Phase 1
- [x] **ZCON-02**: Plugin detects Zotero schema version (6.x vs 7.x) and handles field differences — ✅ Phase 1
- [x] **ZCON-03**: Plugin auto-detects database location on Windows, Mac, and Linux — ✅ Phase 1
- [x] **ZCON-04**: User can manually specify database path in settings — ✅ Phase 1

### Onboarding

- [x] **ONBD-01**: Plugin provides multi-step setup wizard Modal for first-time users — ✅ Phase 4
- [x] **ONBD-02**: User can select 5-15 seed papers to establish interest profile — ✅ Phase 4 (adjusted from fixed 10)
- [x] **ONBD-03**: Plugin extracts keywords and authors from seed papers for profile — ✅ Phase 4 (tags deferred)
- [x] **ONBD-04**: User can skip wizard and configure manually via settings — ✅ Phase 4

### Batch Generation

- [x] **BTCH-01**: Plugin can generate a batch of N candidate items on demand (default: 5) — ✅ Phase 2
- [x] **BTCH-02**: User can request new batch at any time via command or button — ✅ Phase 2
- [x] **BTCH-03**: Batch ranking uses profile similarity (matching keywords and authors) — ✅ Phase 4
- [x] **BTCH-04**: Batch generator never proposes items already in registry (dedup) — ✅ Phase 2

### Triage Dashboard

- [x] **TRIG-01**: Plugin provides card-based ItemView for reviewing batch items — ✅ Phase 2
- [x] **TRIG-02**: Each card has Accept, Reject, and Defer action buttons — ✅ Phase 2
- [x] **TRIG-03**: Card shows metadata preview: title, authors, year, abstract, item type — ✅ Phase 2
- [x] **TRIG-04**: Dashboard shows batch progress indicator (X/5 processed) — ✅ Phase 2

### Quality Gate

- [x] **QUAL-01**: Plugin blocks import if configurable required fields are missing — ✅ Phase 3
- [x] **QUAL-02**: Plugin shows exactly which fields are missing for blocked items — ✅ Phase 3
- [x] **QUAL-03**: Plugin provides zotero://select link to fix item in Zotero — ✅ Phase 3
- [x] **QUAL-04**: User can override quality gate and force import despite warnings — ✅ Phase 3
- [x] **QUAL-05**: Required fields are configurable per item type (e.g., journal article requires DOI, book requires publisher) — ✅ Phase 3

### Note Generator

- [x] **NOTE-01**: Plugin creates markdown note in configurable folder (default: 10_Literature/) — ✅ Phase 1
- [x] **NOTE-02**: Note includes full YAML frontmatter: title, authors, year, DOI, publication, item type — ✅ Phase 1
- [x] **NOTE-03**: Frontmatter includes zotero://select link and citekey — ✅ Phase 1
- [x] **NOTE-04**: Frontmatter includes path to PDF attachment if exists — ✅ Phase 1

### Processing Registry

- [x] **RGST-01**: Plugin tracks state of each Zotero item: unseen, proposed, accepted, rejected, deferred, imported — ✅ Phase 1
- [x] **RGST-02**: Registry persists to plugin data folder as JSON — ✅ Phase 1
- [x] **RGST-03**: Batch generator respects registry states (dedup enforcement) — ✅ Phase 2
- [x] **RGST-04**: Plugin provides stats dashboard: X imported, Y rejected, Z pending — ✅ Phase 2

### Settings

- [x] **SETT-01**: User can configure Zotero database path — ✅ Phase 1
- [x] **SETT-02**: User can configure output folder for literature notes — ✅ Phase 1
- [x] **SETT-03**: User can configure batch size (default: 5) — ✅ Phase 2
- [x] **SETT-04**: User can configure required fields per item type for quality gate — ✅ Phase 3
- [x] **SETT-05**: User can modify profile (re-select seed papers, update preferences) — ✅ Phase 4

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Bulk "import all" button | Defeats core purpose — causes importer's block |
| Built-in PDF reader | Zotero already does this well |
| Custom Zotero metadata fields | Breaks Zotero compatibility |
| Full-text PDF search | Zotero handles this |
| AI-assisted summaries | Complex, external dependencies, defer to v2+ |
| Cloud sync / external services | Local-first architecture requirement |
| Vector database / embeddings | Complexity not justified for MVP |
| Writing to Zotero | Read-only constraint for safety |
