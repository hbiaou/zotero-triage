### Phase 6: Tag Infrastructure & Extraction

**Goal**: Extract tags from Zotero database and integrate into data layer
**Depends on**: Phase 5 (v1.0 complete)
**Requirements**: TAG-01, TAG-02, VAL-01, VAL-02
**Plans**: 3 plans

Plans:

- [x] 06-01: Add annotation filtering and defensive NULL handling to tag extraction
- [x] 06-02: Add schema validation and integrate tags into profile initialization
- [x] 06-03: Verify tag infrastructure with real Zotero 7 database

**Details:**

Tag infrastructure complete with SQL-level annotation filtering (custom-color-*, highlight-*, annotation-*, _*), defensive NULL handling for schema variations, and schema validation with graceful degradation. Tags integrated into ZoteroItem schema and UserProfile with Map<string, number> structure. Verified working with real Zotero 7 database (5000+ items, 500+ tags).

**Key Decisions:**
- Filter annotation tags at SQL level using NOT LIKE patterns for efficiency
- Graceful degradation (empty array) for tag extraction failures
- Non-blocking tag schema validation (tags are optional enhancement)
- Lowercase normalization for consistent matching in Phase 7

**Bugs Fixed:**
- ESCAPE clause syntax error in SQL query (SQLite requires `ESCAPE '\\'` not `ESCAPE '\'`)
- ProfileInitializer constructor argument order reversed in settings.ts

### Phase 7: Tag-Based Recommendations

**Goal**: Tags improve batch relevance through profile scoring and adaptive learning
**Depends on**: Phase 6
**Requirements**: TAG-03, TAG-04, TAG-05, TAG-06
**Plans**: 3 plans

Plans:

- [x] 07-01: Extract top 20 tags from seed papers and implement tag scoring with stemming
- [x] 07-02: Add tag-based adaptive learning with weight decay and settings configuration
- [x] 07-03: Verify tag recommendations work end-to-end with real Zotero database

**Details:**

Tag-based scoring integrated into recommendation engine with Porter stemming for linguistic normalization. Profile initialization extracts top 20 most frequent tags from seed papers with frequency-based weighting. Tag scoring uses case-insensitive stemmed matching with linear multi-match strategy (sum all matching weights). Adaptive learning updates tag weights from accept/reject feedback with exponential moving average decay (0.95 factor) every 10 events. User-configurable tag weight slider (0.0-3.0, default 1.5) in settings.

**Key Decisions:**
- Tag weight positioned at 1.5 (between keywords 2.0 and authors 1.0)
- Top 20 tags from seed papers balances coverage vs noise
- Linear multi-match scoring (no diminishing returns, fair for diverse papers)
- Items without tags score 0 (neutral, not penalized)
- Multi-word tags use exact match after stemming (preserve semantic phrases)
- Decay every 10 feedback events prevents permanent weight extremes

**Bugs Fixed:**
- Debug logging missing in RecommendationEngine and AdaptiveLearner
- Profile updates not persisting (getProfile() created new Map instances)
- Stemmer package dependency (replaced with inline implementation)

### Phase 8: UX Enhancements (Progress, Validation, Search & Modal UX)

**Goal**: Users receive clear feedback during operations, understand validation requirements, can efficiently find items, and have smooth interaction flows
**Depends on**: Phase 6 (tag infrastructure not required for UX features)
**Requirements**: UX-01 through UX-10
**Plans**: 3 plans

Plans:

- [x] 08-01: Add throttled progress updates, empty profile warnings, and enhanced override modal guidance
- [x] 08-02: Add search/filter to seed paper picker and batch view
- [x] 08-03: Fix modal sizing and preserve scroll position during item interactions

**Details:**

Progress tracking throttled to 500ms time-based updates with 100-item batch callbacks during scoring. Empty profile detection shows 10-second notice guiding users to enrich metadata in Zotero. Override modal displays field examples and expandable explanations with progressive disclosure pattern. Validation warnings aggregated into single summary notice after batch generation. Real-time search filtering by author/title/tags in both seed paper picker and batch view. Search queries persist across state changes. Responsive modal sizing (90vw max-width) eliminates horizontal scrolling. Scroll position preserved during item selection using requestAnimationFrame timing.

**Key Decisions:**
- Progress throttle 500ms allows max 2 updates/second
- Batch update every 100 items (50 updates for 5000-item library)
- Empty profile warning shown after creation but before return
- Field help uses progressive disclosure (examples visible, explanations expandable)
- Search uses case-insensitive substring match (simple, performant)
- Search scope covers title, authors, tags (core identifying fields)
- No debounce on search (filtering fast enough for instant feedback)
- Scroll restoration uses requestAnimationFrame after DOM update

**Bugs Fixed:**
- Wizard modal sizing not working (CSS targeted wrong class)
- Search inputs not accepting text (value restoration missing)
